# Version Control Setup per Engine

Blocks to merge into the project's `.gitignore` and `.gitattributes`. Merge means: keep every line the
project already has, add the missing ones, never duplicate. Every block assumes the GameForge state
lines are already present:

```gitignore
# GameForge session state (local, per machine)
production/session-state/
production/session-logs/
```

The GameForge commit hook denies commits that add files at or above `lfs_threshold_mb` (default 20 MB)
that Git LFS is not tracking. LFS patterns below keep normal work under that guard. Check your Git
host's LFS storage and bandwidth quota before committing large audio or video.

Common to all engines:

```gitignore
.DS_Store
Thumbs.db
*.swp
.env
.env.*
!.env.example
```

## Godot 4

### `.gitignore`

```gitignore
# Godot 4 cache and imported data (regenerated by the editor)
.godot/
# Android build template (reinstall from the editor)
/android/
# Local export output
/build/
/exports/
# Mono/.NET build output (C# projects)
.mono/
mono_crash.*.json
```

Commit these, even though they look generated:
- `*.import` files next to assets (import settings, not imported data).
- `*.uid` files (Godot 4.4+ resource UIDs). Deleting or ignoring them breaks references for teammates.
  The GameForge file guard denies editing them by hand; let the editor manage them.
- `export_presets.cfg`. Current Godot 4 releases keep export credentials in
  `.godot/export_credentials.cfg`, which `.godot/` already ignores. Read the presets file once for
  stray passwords anyway.

### `.gitattributes`

```gitattributes
# Normalize text; Godot text formats diff and merge well
* text=auto eol=lf
*.gd text
*.tscn text
*.tres text
*.godot text
*.cfg text
*.gdshader text

# Binary assets to Git LFS
*.png filter=lfs diff=lfs merge=lfs -text
*.jpg filter=lfs diff=lfs merge=lfs -text
*.webp filter=lfs diff=lfs merge=lfs -text
*.psd filter=lfs diff=lfs merge=lfs -text
*.kra filter=lfs diff=lfs merge=lfs -text
*.aseprite filter=lfs diff=lfs merge=lfs -text
*.blend filter=lfs diff=lfs merge=lfs -text
*.glb filter=lfs diff=lfs merge=lfs -text
*.gltf text
*.fbx filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.ogg filter=lfs diff=lfs merge=lfs -text
*.mp3 filter=lfs diff=lfs merge=lfs -text
*.ttf filter=lfs diff=lfs merge=lfs -text
*.otf filter=lfs diff=lfs merge=lfs -text
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.webm filter=lfs diff=lfs merge=lfs -text
```

Small pixel-art projects can keep `*.png` in plain git if the whole repository stays small; decide
once, early, because moving history into LFS later means rewriting it.

## Unity 6

Editor settings first (Project Settings > Editor):
- **Asset Serialization: Force Text.** Scenes, prefabs and ScriptableObjects become YAML that diffs.
- **Version Control: Visible Meta Files.** Every asset has a `.meta` with its GUID. Never ignore or
  delete `.meta` files; a lost `.meta` breaks every reference to that asset. The GameForge file guard
  asks before an agent edits one.

## Unreal Engine 5

`.uasset` and `.umap` are binary and cannot be merged. Put them in LFS from the first commit and mark
them `lockable`, so a teammate runs `git lfs lock Content/Maps/Level01.umap` before editing.
Larger Unreal teams often use Perforce instead of git; that is a team decision for
`/gameforge:game-technical-director`, not a setup default.

### `.gitignore`

```gitignore
Binaries/
DerivedDataCache/
Intermediate/
Saved/
.vs/
.idea/
*.sln
*.suo
*.opensdf
*.sdf
*.VC.db
*.VC.opendb
*.xcworkspace
*.xcodeproj
Plugins/*/Binaries/
Plugins/*/Intermediate/
# Packaged builds
/Build/
/Packaged/
```

### `.gitattributes`

```gitattributes
* text=auto
*.cpp text diff=cpp
*.h text diff=cpp
*.ini text
*.uproject text

*.uasset filter=lfs diff=lfs merge=lfs -text lockable
*.umap filter=lfs diff=lfs merge=lfs -text lockable
*.png filter=lfs diff=lfs merge=lfs -text
*.tga filter=lfs diff=lfs merge=lfs -text
*.exr filter=lfs diff=lfs merge=lfs -text
*.psd filter=lfs diff=lfs merge=lfs -text
*.fbx filter=lfs diff=lfs merge=lfs -text
*.blend filter=lfs diff=lfs merge=lfs -text

*.mp4 filter=lfs diff=lfs merge=lfs -text
*.dll filter=lfs diff=lfs merge=lfs -text
*.lib filter=lfs diff=lfs merge=lfs -text
```

Turn on `git config lfs.locksverify true` for the repository once locking is in use.

## Web (Three.js, R3F, Babylon, PlayCanvas, Phaser, PixiJS, Kaplay, Excalibur)

### `.gitignore`

```gitignore
node_modules/
dist/
build/
.vite/
.parcel-cache/
coverage/
test-results/
playwright-report/
*.local
```

### `.gitattributes`

```gitattributes
* text=auto eol=lf

# Source files only: masters that never ship to the browser
*.blend filter=lfs diff=lfs merge=lfs -text
*.psd filter=lfs diff=lfs merge=lfs -text
*.kra filter=lfs diff=lfs merge=lfs -text
*.aseprite filter=lfs diff=lfs merge=lfs -text
*.fbx filter=lfs diff=lfs merge=lfs -text
*.wav filter=lfs diff=lfs merge=lfs -text
*.flac filter=lfs diff=lfs merge=lfs -text
```

Runtime assets that ship (`.glb`, `.ktx2`, `.webp`, `.ogg`, `.mp3`) are usually small after
optimization and should stay in plain git if the site deploys straight from the repository:
branch-based GitHub Pages serves LFS pointer files instead of the real binaries. If they must be in
LFS, deploy from CI with LFS checkout enabled (for GitHub Actions, `actions/checkout` with
`lfs: true`) and verify a deployed asset is not a ~130-byte pointer file.

Web portals cap download size (CrazyGames asks for an initial download of 20 MB or less for its
mobile homepage; YouTube Playables under 30 MiB initial), so a web repository with many large
runtime files has a build problem, not a git problem. Route that to `/gameforge:game-web-publish`.

## Verify

```bash
git lfs track            # lists tracked patterns from .gitattributes
git status --short       # .godot/, Library/, Intermediate/, node_modules/ must not appear
git lfs ls-files         # after the first commit: binaries listed here, not in plain git
```

If a large binary was committed before LFS tracking, do not rewrite history during setup. Note it in
the report and let the user decide (`git lfs migrate` rewrites history and needs a coordinated
force-push).
